# 仕様書 (SPEC.md)

## 1. 目的・ゴール

AI自動テストのベストプラクティスを実証するためのテストベッド構築。

## 2. 技術スタック

Next.js (App Router), Tailwind CSS, shadcn/ui, PostgreSQL, Prisma, NextAuth, Vitest, Playwright.

## 3. 機能要件 (BDD形式)

### 3.1 認証・権限管理

Admin / Userによるルーティング制御と403エラー。

**Feature: ロールベースアクセス制御**

```gherkin
Scenario: 一般ユーザーが管理者画面にアクセスする
  Given ユーザーが "User" ロールでログインしている
  When "/admin" にアクセスする
  Then 403エラーページが表示される

Scenario: 管理者が管理者画面にアクセスする
  Given ユーザーが "Admin" ロールでログインしている
  When "/admin" にアクセスする
  Then 管理者ダッシュボードが表示される
```

### 3.2 網羅的フォーム要素

shadcn/uiのInput, Select, DatePicker, Checkbox等を用いた個別独立フォーム。

**Feature: フォーム要素の検証**

```gherkin
Scenario: 各種入力フォームが正しく動作する
  Given 検証用入力画面 "/forms" にアクセスしている
  When 各フォーム要素に有効な値を入力する
  Then バリデーションが成功し、送信ボタンが有効になる

Scenario: 必須フィールドが未入力の場合
  Given 検証用入力画面 "/forms" にアクセスしている
  When 必須フィールドを空のまま送信する
  Then エラーメッセージが該当フィールドの下部に表示される
```

### 3.3 条件付きバリデーション

特定の入力によって他項目の必須ルールが動的に変わる検証。

**Feature: 条件付きバリデーション**

```gherkin
Scenario: "その他" を選択すると詳細入力が必須になる
  Given 検証用入力画面 "/forms" の条件付きバリデーションセクションにいる
  When カテゴリで "その他" を選択する
  Then "詳細説明" フィールドが必須に変わる
  And "詳細説明" を空のまま送信するとエラーが表示される

Scenario: "その他" 以外を選択した場合
  Given 検証用入力画面 "/forms" の条件付きバリデーションセクションにいる
  When カテゴリで "カテゴリA" を選択する
  Then "詳細説明" フィールドは任意のまま
```

## 4. UI/UXデザイン要件

### 4.1 デザインシステムとトーン＆マナー

- **ベースUI**: `shadcn/ui` のコンポーネントデザインに準拠すること。
- **スタイリング**: Tailwind CSS のユーティリティクラスを想定した構造にすること。
- **レイアウト**: モバイルファーストの完全レスポンシブ対応（ブレイクポイント: sm, md, lg）。

### 4.2 画面レイアウト構成

1. **認証画面 (`/login`)**:
   - 画面中央に配置されたシンプルなカード型レイアウト。
   - メールアドレス/パスワード入力、および「Sign in with GitHub/Google」等のOAuthボタンを配置。
2. **検証用入力画面 (`/forms`)**:
   - 左側にサイドバーナビゲーション（入力タイプ別のアンカーリンク）。
   - 右側メインエリアに、shadcn/ui の各種フォーム要素（Input, Select, DatePicker, Switch等）をカード単位で整理して配置。
3. **管理者/一般画面 (`/admin`, `/user`)**:
   - ヘッダーに現在のログインユーザー情報とロール（権限）バッジを表示。
   - 管理者画面にはダッシュボード（KPIカードやテーブル）、一般画面にはシンプルなプロファイル情報を配置。

### 4.3 状態（States）の明示

モック生成時は以下の状態（UI Feedback）も視覚的に表現すること。

- **エラー状態**: バリデーション失敗時の赤枠（`border-destructive`）と、フィールド下部のエラーテキスト。
- **ローディング状態**: Submitボタンのスピナー表示や、コンポーネントのスケルトン表示。
- **無効状態**: 送信不可時のボタングレーアウト。

## 5. テスト基準と検証アプローチ

| テストレベル | ツール | 対象 | カバレッジ目標 |
|---|---|---|---|
| ユニットテスト | Vitest | Zodスキーマ、ユーティリティ関数、カスタムフック | 80%以上 |
| 結合テスト | Apidog + Postgres MCP | APIエンドポイント、DB操作 | 主要パス100% |
| E2Eテスト | Playwright MCP | ユーザーフロー全体 | 主要シナリオ100% |

### テスト命名規約

```
[対象].test.ts      // ユニットテスト
tests/e2e/*.spec.ts // E2Eテスト
```
